# Operations

## Running

```bash
docker compose up --build          # postgres, redis, api, worker, web
docker compose logs -f api worker  # follow
docker compose down                # stop
```

Services: API `:8000`, dashboard `:3000`, PostgreSQL `:5432`, Redis `:6379`.

## Migrations

```bash
make migrate                       # alembic upgrade head
make revision m="add x table"      # autogenerate a new revision
cd apps/api && .venv/bin/alembic downgrade -1
```

The API container runs `alembic upgrade head` on start. Review every autogenerated
revision before committing it.

## Health

`GET /api/system/health` is unauthenticated and probes each component for real:

```
database    HEALTHY    PostgreSQL round trip + migration revision
queue       HEALTHY    Redis PING + INFO + queue depth
storage     HEALTHY    Backend writability / bucket reachability
ffmpeg      AVAILABLE  `ffmpeg -version` executed
youtube     NOT CONFIGURED
llm_provider    NOT CONFIGURED
voice_provider  NOT CONFIGURED
encryption      NOT CONFIGURED
```

Overall status is `UNHEALTHY` only when a *critical* component (database, queue) is
down. A missing optional integration is reported, not treated as an outage.

`GET /api/system/capabilities` (authenticated) returns the same provider information
with the exact environment variables each one is missing.

## Jobs

- `GET /api/jobs?status=FAILED` — inspect failures
- `GET /api/jobs/{id}` — job detail with its log lines
- `POST /api/jobs/{id}/retry` — re-queue a `FAILED`/`CANCELLED` job for one more run
- `POST /api/jobs/{id}/cancel` — cancel queued work

Permanent failures (`permanent_failure: true`) are not retried automatically; they
indicate configuration problems, not transient faults.

## Emergency stop

`POST /api/channels/{id}/automation/emergency-stop` immediately:

1. sets `emergency_stop`,
2. disables autopilot and auto-publishing,
3. cancels queued `youtube_upload`, `automation_tick` and `automation_advance` jobs.

Clearing the stop does **not** re-enable automation — that is a separate, audited act.

## Backups

State worth backing up lives entirely in PostgreSQL plus the object store.

```bash
docker compose exec postgres pg_dump -U nexora -Fc nexora > nexora-$(date +%F).dump
docker compose exec -T postgres pg_restore -U nexora -d nexora --clean < nexora-YYYY-MM-DD.dump
```

Rendered media lives in the `media-data` volume (local backend) or your S3 bucket.

**`ENCRYPTION_KEY` must be backed up separately and securely.** Without it, stored
OAuth tokens cannot be decrypted after a restore and every channel must be reconnected.
Rotating the key requires reconnecting each channel.

## Resource notes

The development target is a 8 GB / Intel i3 Windows machine:

- Database pool is capped at 5 connections + 5 overflow.
- Redis runs with `maxmemory 128mb` and no persistence — it holds no durable state.
- Renders stream through FFmpeg rather than loading media into memory.
- The dashboard does no background polling and paginates every table.
